# 11 — عقد بصمة الملف المقترح (Import Fingerprint Contract Proposal)

**التدقيق:** ET-2026-10-20 · **الحالة: `PROPOSED_NOT_APPLIED`** — لا كود ولا ترحيل ولا تعديل في هذا الملف.
**الهدف:** ربط `importId` بهوية ملف **ثابتة** ورفض الالتباس بصمت.

## 11.1 العقد المقترح (مستوى التصميم)

```
المفتاح المنطقي للاستيراد  =  (actor_id, importId)
هوية الملف                  =  file_fingerprint = SHA-256( canonical_file_bytes )
سياسة المطابقة             =  same importId  ⇒  same file_fingerprint  ⇒  resume
                             same importId  ⇒  different file_fingerprint ⇒  409 IMPORT_FILE_MISMATCH
```

## 11.2 ما هو «الملف» بالضبط؟ (خياران، لهما أثران مختلفان)

| الخيار | التعريف | المزايا | العيوب | التوصية |
|---|---|---|---|---|
| **خام** | SHA-256 لبايتات الملف كما وصلت | أبسط وأوضح؛ يلتقط أي اختلاف بايت (بما فيه ترتيب الصفوف) | حسّاس لأي اختلاف غير ذي معنى (نهاية سطر CRLF/LF، ترميز، سطر أخير فارغ) | **لا** |
| **مُطبَّع (مقترح)** | SHA-256 على **الشكل المُحلَّل**: (أ) رؤوس الأعمدة بعد `trim`، (ب) كل صف بعد `trim` للخلية + توحيد `\r\n`، (ج) ترتيب الصفوف **كما هو** | يطابق «نفس الملف منطقيًا»؛ يتسامح مع فروق محارف نهاية السطر | حسّاس لترتيب الصفوف (وهو المطلوب: إعادة الترتيب تُعدّ ملفًا مختلفًا ⇒ تُرفض) | **نعم** |

> **قرار مطلوب:** هل تُعتبر إعادة ترتيب الصفوف «نفس الملف»؟ التوصية: **لا** (لأن هوية الصف = رقم السطر ⇒ الترتيب يغيّر هوية الصف). أي أن البصمة المُطبَّعة **تحافظ على ترتيب الصفوف**.

## 11.3 الأثر على الأداء

| البند | التقدير | ملاحظة |
|---|---|---|
| حساب البصمة | SHA-256 على ~CSV بحجم K ⇒ أجزاء من الثانية | يُحسب مرة واحدة لكل طلب commit |
| التخزين | 32 بايت (hex) لكل عملية | ترحيل إضافي (إضافة فقط) |
| المقارنة | ثابت | — |
| الخيار الأثقل | بصمة على بايتات خام + بصمة مُطبَّعة معًا | غير لازم |

## 11.4Changes على المخطط (مقترح، غير مطبَّق)

| العنصر | الوصف |
|---|---|
| `customer_import_operations` | `+ file_fingerprint TEXT` (NOT NULL بعد الترحيل) · `+ fingerprint_kind TEXT` (`NORMALIZED_V1`) · `+ parser_version TEXT` |
| قيد | `UNIQUE(actor_id, import_id)` (مطبَّق كـPRIMARY منطقي اليوم) — **يُقترح** إضافة قيد فريد صريح على (actor_id, import_id) بدل الاعتماد على `id` كنص حرّ |
| الفهرس | فهرس على `file_fingerprint` للبحث التشخيصي (اختياري) |
| الترحيل | `0008_import_fingerprint.sql` على نمط 0005–0007 (**إضافة فقط**)، مع `ALTER TABLE … ADD COLUMN` بقيمة NULL أولًا ثم تعبئة العمليات القديمة بـ`fingerprint_kind='LEGACY_UNVERIFIED'` |

## 11.5 دلالات الأخطاء (مقترحة)

| الحالة | الرمز | HTTP | الرسالة (مقترحة) |
|---|---|---|---|
| نفس `importId` بملف مختلف | `IMPORT_FILE_MISMATCH` | **409** | «This import id was already used for a different file. Start a new import or resume the original file.» |
| نفس `importId` لفاعل آخر | `IMPORT_ID_CONFLICT` | 409 | (موجود اليوم — يُبقي) |
| نفس الملف، نفس الفاعل | — | 200/201 | استئناف عادي مع `skipped` |
| عملية قديمة بلا بصمة | `IMPORT_LEGACY_UNVERIFIED` | 409 | «This import predates file fingerprinting; resume it with the original file or start a new import.» |

## 11.6 خطة التوافق

| المرحلة | الإجراء | المخاطرة |
|---|---|---|
| 1 | إضافة الأعمدة nullable + تعبئة `LEGACY_UNVERIFIED` | صفر (إضافة فقط) |
| **الخيار الأثقل** | بصمة على بايتات خام + بصمة مُطبَّعة معًا | غير لازم |
| 3 | بعد فترة، `ALTER … SET NOT NULL` + `fingerprint_kind` إلزامي | متوسطة: تحتاج عدّاد عمليات قديمة |
| 4 | تفعيل `IMPORT_FILE_MISMATCH` على كل العمليات | منخفضة بعد 2/3 |

**لا كسر للعقد العام:** `importId` يبقى اختياريًا (يُولَّد عند الغياب كما اليوم)؛ التغيّر هو **الرفض عند التعارض** فقط.

## 11.7 اعتبارات الخصوصية

| البند | القاعدة |
|---|---|
| ما يُخزَّن | البصمة (32 بايت) + `fingerprint_kind` + الإصدار — **لا محتوى CSV ولا أسماء** |
| ما لا يُسجَّل | لا تُسجَّل البصمة الجزئية ولا البايتات الخام في السجلات |
| أسماء العملاء | تبقى في `customer_import_rows.legal_name` ⇒ تحتاج سياسة retention مستقلة (انظر 10.6) |

## 11.8 بديل مُبسَّط (إن رفض المالك تغيير المخطط)

| الفكرة | الأثر | التقييم |
|---|---|---|
| تخزين `rows_digest` (SHA-256 لـ JSON المرتَّب للصفوف) داخل `summary_json` القائم | لا ترحيل؛ المقارنة في الكود | **جزئي**: يمنع الالتباس بين ملفين مختلفين في نفس العملية، لكنه لا يمنع إعادة الترتيب (لأن JSON مرتَّب) — تحتاج ترتيبًا ثابتًا غير مرتَّب |
| **الأثر** | - | - |

**التوصية النهائية:** خيار البصمة المُطبَّعة + `UNIQUE(actor_id, import_id)` + `409 IMPORT_FILE_MISMATCH`، مع مراحل توافق من 4 خطوات.
