## 2. ما هو جاهز فعلًا

1. **نطاق وظيفي واضح:** عرض سعر مستقل، `Proforma = Quotation`، رقم يدوي، ربط قبل/بعد الحالة، عدة عروض لفاتورة واحدة.
2. **نموذج بيانات مفاهيمي:** `quotations`, `quotation_items`, `quotation_revisions` (اختياري)، `quotation_case_links`، وروابط الفاتورة في W3.
3. **خيارات دورة الحياة:** A/B/C، مع توصية غير ملزمة.
4. **مصفوفة صلاحيات مقترحة:** خمس صلاحيات، غير منفذة.
5. **واجهات API مقترحة:** ثمانية مسارات، مع idempotency وversion.
6. **12 سيناريو UAT** مع نتائج متوقعة.
7. **استراتيجية ترحيل واختبار** على قاعدة اصطناعية مأهولة، بلا رقم migration نهائي.
8. **قائمة قرارات مالك** قبل البدء.

## 6. استراتيجية الاختبار

### 6.1 وحدات

- حساب المجاميع، تحويل الحالة، منع الانتقالات غير المسموحة.
- provenance: نسخ بند لا يعدّل الأصل.
- تفرد الرقم (إن حُسم النطاق).
- صلاحيات: كل فعل/نطاق.

### 6.2 API/تكامل

- إنشاء/تعديل/إصدار/ربط/PDF.
- 403/404/409/422.
- idempotency وversion.
- عدم تسريب بيانات حالة أخرى.

### 6.3 Playwright موجّه

- سيناريوهات W2-UAT-01..10 على جذر جديد.
- AR/EN وRTL/LTR.
- PDF إن أمكن محليًا.
- لا E2E كامل؛ W5 لاحقًا.

### 6.4 Migration

- قاعدة اصطناعية مأهولة: عملاء/حالات/فواتير/مستخدمون/صلاحيات.
- قبل/بعد: counts + hashes + FK + فهارس.
- اختبار فشل آمن وتراجع.
- لا قاعدة مطور/remote.
