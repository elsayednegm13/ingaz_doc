- تتوقف الأداة عند تغيير قواعد أعمال معلقة، أو تجاوز القائمة، أو خطر على البيانات، أو أي وصول محظور، أو تغيير سحابي، أو تغيّر الحزم/العقود عن خط الأساس المثبت.

### W1 — سلامة البيانات والتكامل (M02)

**داخل تكليف واحد وبوابات متتابعة:**

1. `W1-G0 — Safety/Source Preflight`: إعادة التحقق من المصدر النهائي وإعدادات العزل المبلّغ بها في M01، وتثبيت إصدارات الحزم، وعدم افتراض غياب مشاكل Vite env/transport. تهيئة جذر/جذور اصطناعية جديدة فقط. إذا ظهر سلوك يهدد قاعدة المطور أو الجذور التاريخية: `STOP`.
2. `W1-G1 — Populated D1 Official Migration`: إنشاء قاعدة صناعية على `0007` مع عملاء/حالات/فواتير وإصدارات مستندات/صلاحيات/مفاتيح idempotency/استيراد legacy/علاقات متعددة. توثيق counts + canonical hashes + FK/index/constraints قبل وبعد. تطبيق `0008` بواسطة Wrangler D1 **المحلية فقط** مع config صريح للجذر المملوك؛ تحقق من حفظ التاريخ وفشل آمن. لا اختبار بقاعدة المطور.
3. `W1-G2 — Real Integration D-1/D-2/D-3`: تجربة Worker/Hono/Better Auth/D1 الفعلية على بيئة اصطناعية، replay بعد تغير الصلاحيات وحالات الانتهاء والسباق، بصمات CSV والاستئناف، bootstrap وتعويض الفشل وسجلات الحوادث؛ لا الاعتماد على fake-auth فقط.
4. `W1-G3 — P1 Security/Integrity`: اختبارات مصفوفة أدوار reports scope + global privilege، منع cascade عند وجود نسخة/مراجعة، expected container count/booking slots، Replay لكل المسارات المحمية، منع وصول عدد المديرين النشطين لصفر تحت التزامن. أي سياسة تجارية غير محسومة (مثل الحذف النهائي للمستندات) تظل `BLOCKED_CONTRACT` ولا تُخترع.
5. `W1-G4 — Focused Regression & Reliability`: targeted E2E + API regression مع فحص E2E TypeScript مستقل؛ حفظ المحاولات الخام كافة، ومعالجة/تصنيف شذوذ بدء الخدمة؛ توثيق مخاطر Vite `.env*` وpost-spawn failure containment. فحص التسلسل والتراجع الممكن من الجذور الجديدة.
6. `W1-G5 — Transition Review`: Typecheck/lint، الاختبارات المرتبطة مرتين عند الحاجة لتأكيد الثبات، مطابقة أثر الكود والبيانات والصلاحيات والعقود، 0 مخاطر P0/P1 مفتوحة ضمن نطاق W1، تقرير عربي `PASS/PARTIAL/BLOCKED/FAIL` ثم `STOP`.

**ممنوع في W1 بدون إذن مستقل:** بيانات مطور/إنتاج، أسرار حقيقية، Git mutations، Cloudflare remote، R2 remote، تعديل BR التجاري، بناء Quotation، إعادة كتابة migrations `0001..0008`. لا تمحو أدلة الجذور الاصطناعية السابقة.

## 4. بروتوكول أداة التنفيذ — «أسرع مع الإثبات»

**مرحلة واحدة = برومت واحد + تفويض واحد + تقرير انتقال واحد**. تتحرك الأداة عبر البوابات الفرعية داخل نفس التفويض **فقط إذا** نتيجة البوابة السابقة `PASS` وكانت الخطوة اللاحقة مصرحًا بها صراحةً، وبلا قرار أعمال معلق. عند `PARTIAL/BLOCKED/FAIL` تتوقف ولا تصنع فروع معالجة خارج قائمة السماح.

**البداية:** اقرأ `AGENTS.md`, `AGANT.MD`, `HANDOFF.MD`، ثم هذه الخطة وBR/OD، ثم افحص المصدر الحالي و`docs/transition-*` المسموح دون لمس الجذور المحمية؛ صَنّف `OBSERVED_SOURCE`, `OBSERVED_RUNTIME`, `PRIOR_REPORT`, `INFERRED`, `UNVERIFIED`.

**أثناء العمل:** اجعل كل تعديل صغيرًا وقابلًا للتتبع؛ حافظ على API/contracts، migrations القديمة والـsnapshots وسجل المستندات، وتعامل مع الأخطاء `fail closed` بلا SQL/stack للمستخدم. لا تكرر اختبارات كاملة بلا سبب أثناء كل سطر؛ استخدم targeted tests ثم project-wide regression بعد ثبات النسخة، مع حفظ سجل كل محاولة.

**أدلة كل موجة:**
1. `00_SCOPE_AUTHORIZATION_AR.md` — الحدود المسموحة/الممنوعة.
2. `01_SOURCE_DELTA_AND_DEPENDENCY_MAP_AR.md` — التغيير، الملف، الأثر، قبل/بعد.
3. `02_TEST_MATRIX_AR.md` — مصفوفة requirements → tests → failures/retries.
4. `03_DATA_INTEGRITY_AND_ACL_AR.md` — بيانات/ترحيلات/صلاحيات/تزامن.
5. `04_RUNTIME_PERFORMANCE_UI_AR.md` — إثبات محلي/واجهة/تحفظات.
6. `05_RISKS_OPEN_DECISIONS_AR.md` — P0/P1/P2 والقرارات التجارية.
7. `06_FINAL_TRANSITION_GATE_AR.md` — PASS/PARTIAL/BLOCKED/FAIL وGO/NO-GO ونقطة التوقف.
8. `evidence/` — raw stdout/stderr JSON/TAP، مسارات الجذور المملوكة، hashes، logs منقحة دون أسرار؛ ملفات كل محاولة مستقلة ولا تُستبدل.

يمكن دمج الأجزاء التي لا تنطبق على موجة محددة تحت عنوان `NOT_APPLICABLE` بالأسباب، **دون اختلاق اختبار أو نجاح**. لا تتطلب كل موجة كتابة 7 تقارير مطولة؛ المطلوب حقول الدليل كاملة وملف انتقال واحد مفهرس أو ملفات قصيرة بحسب الحاجة.

**الثوابت:**
- قاعدة المطور `.wrangler/state` لا تُقرأ/تُفتح/تُنسخ/تُرحّل؛ الجذور التاريخية لا تُلمس؛ `.dev.vars*` الحقيقية لا تُقرأ؛ لا تنظيف شامل/قتل عمليات أجنبية.
- `Git` غير مصرح بالتعديل عليه تلقائيًا (commit/push/reset/clean/stash/checkout). فحص Git القراءة فقط يحتاج أن يكون مشمولًا في تفويض الموجة إن طلبناه؛ لا افتراض أن إذن التشغيل المحلي يسمح به.
- لا Cloudflare remote ولا Staging ولا Production دون إذن مختلف عن صلاحيات الاختبارات المحلية.
- لا تخفيف tests/guards للوصول إلى PASS؛ لا إخفاء محاولات فشل؛ لا إدخال بيانات تمثيلية على أنها حقيقية.
- لا تعديل migrations `0001..0008`، ولا ترحيل حقيقي على قاعدة المطور؛ migrations المزايا الجديدة تكون إضافية بعد مراجعة منفصلة وموافقة موثقة.
- عند اكتشاف احتياج تعديل ملف خارج القائمة أو سياسة تجارية غير محسومة: سجل القرار و`STOP` بدل التجاوز.
